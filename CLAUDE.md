## Project Overview

An end-to-end, human-in-the-loop automated video generation system that produces short-form and long-form content for platforms like **YouTube** and **TikTok**. The pipeline takes a topic in → outputs a published video out, with a human review checkpoint in the middle.

---

## Architecture: 5-Phase Pipeline

```
[Topic/Brief]
     │
     ▼
Phase 1: Orchestration & Script Generation (CrewAI + Claude)
     │  → Produces: master JSON blueprint (scenes, voiceover, prompts)
     ▼
Phase 2: Audio & Asset Generation (ElevenLabs + Whisper + Kling/fal.ai/Pexels)
     │  → Produces: MP4 B-rolls, WAV audio, word-level timestamps
     ▼
Phase 3: Human-in-the-Loop Review Dashboard (React)
     │  → Human: preview, edit captions, swap clips, approve/lock JSON
     ▼
Phase 4: Composition & Rendering (Remotion — primary / FFmpeg — fallback)
     │  → Produces: final rendered MP4
     ▼
Phase 5: Automated Distribution (n8n webhook → YouTube/TikTok APIs)
```

---

## Phase 1 — Orchestration & Script Generation

**Framework:** CrewAI (multi-agent routing)
**LLM:** Claude (script drafting, optimized per platform)

### Strict JSON Output Schema (per scene)

```json
{
  "scene_id": "string",
  "voiceover_text": "string",
  "target_duration_seconds": "number",
  "broll_prompt": "string (highly specific, used for AI generation or stock search)",
  "platform": "youtube | tiktok"
}
```

**Rules:**
- TikTok scenes: fast hooks, punchy lines, ≤5s per scene preferred
- YouTube scenes: narrative flow, can be longer, must have strong open + close
- Every scene MUST have a `broll_prompt` — no empty fields allowed
- Output must be valid, parseable JSON — no prose, no markdown wrapping

## Phase 2 — Audio & Asset Generation

### Voice (TTS)
- Provider: **ElevenLabs**
- Input: `voiceover_text` per scene from master JSON
- Output: per-scene audio file (`.wav` or `.mp3`)

### Timestamps
- Tool: **Whisper** (word-level transcription)
- Purpose: extract precise word-level timestamps from audio → powers dynamic caption sync
- Output: per-scene timestamp JSON aligned to audio

### B-Roll Acquisition (two paths)

| Path | Tool | When to use |
|------|------|-------------|
| **Synthetic** | Kling AI or fal.ai | Custom scenes, brand-specific, unique visuals |
| **Stock** | Pexels API | Generic filler, fast fallback, lower cost |

**Logic:** Try synthetic first for prompts flagged as `custom`. Fall back to Pexels for generic prompts or on API failure.

---

## Phase 3 — Human-in-the-Loop Review Dashboard

**Framework:** React (lightweight, rapid prototype in Cursor)

### Required Features

| Feature | Description |
|---------|-------------|
| Load blueprint | Ingest master JSON + associated MP4s + audio per scene |
| Scene preview | Scrub through each scene with audio sync |
| Caption editing | Edit `voiceover_text` inline for spelling/accuracy fixes |
| B-roll swap | Trigger re-generation of a specific scene's clip if unsatisfactory |
| Approve & lock | Finalize JSON state — locked JSON is what gets sent to renderer |

### State Model
- `pending` → `in_review` → `approved` (locked) — no rendering until state = `approved`
- Edits reset state back to `in_review` to prevent stale approvals

---

## Phase 4 — Composition & Rendering

### Primary Engine: **Remotion**

Chosen for: animated word-by-word captions, motion graphics, reusable React components, browser-based preview while coding.

**Use Remotion when:**
- Faceless channel with stylized animated captions
- Word-level caption pop animations (Framer Motion)
- Reusable scene templates (Lower Thirds, Title Cards)

### Fallback Engine: **FFmpeg**

Use for: rapid simple concatenation, minimal server resources, no motion graphics needed.

**Use FFmpeg when:**
- Simple clip-A + clip-B + audio stitching
- Server-side rendering with tight resource constraints
- No animated overlays required

### Decision Rule (enforced in code, not just docs)
```
if scenes require animated captions OR motion graphics:
    renderer = "remotion"
else:
    renderer = "ffmpeg"
```

---

## Phase 5 — Automated Distribution

- **Trigger:** n8n webhook fires once final MP4 is confirmed rendered
- **Metadata source:** Phase 1 JSON (title, description, hashtags generated by Claude)
- **Targets:** YouTube API, TikTok API
- **Rule:** Distribution is non-destructive — never overwrite a published video. Each job gets a unique asset ID tracked in the master JSON.

| Decision | Choice | Reason |
|----------|--------|--------|
| Orchestration | CrewAI | Multi-agent routing, proven for pipeline tasks |
| Script LLM | Claude | Strong structured JSON output, platform-aware writing |

| Renderer (primary) | Remotion | Animated captions, component reuse |

| Automation | n8n | Webhook-driven, no-code friendly |

## Development Rules for Claude Code & Agents

1. **Never skip the review gate.** No rendering until JSON state = `approved`.
2. **All external API calls are mockable.** Add a `MOCK_APIS=true` env flag — all integrations must work in mock mode for local dev.
3. **Schema first.** Any change to the JSON blueprint schema must update `schemas/` before touching any consuming code.
4. **One job = one folder.** Each generation run gets its own `data/jobs/<job_id>/` directory. Never mutate another job's data.
5. **Renderer is a plugin.** The renderer choice (Remotion vs FFmpeg) must be swappable via config, not hardcoded.
6. **No API keys in code.** All credentials via `.env` only. `.env` is always in `.gitignore`.
7. **Idempotent re-runs.** Re-triggering any phase for the same job ID must not duplicate assets — check existence first.
